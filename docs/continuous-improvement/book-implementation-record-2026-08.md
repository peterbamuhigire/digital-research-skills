# Book implementation record: research and Linux engines

Author: Peter Bamuhigire | techguypeter.com | +256 784 464 178

This record documents what was implemented from the seven books selected for the research and operations pass. The original book files remain outside the repositories; this is a synthesis and implementation trace, not a reproduction.

## Admitted source limits

| Source | Implementation status | Limitation |
|---|---|---|
| LEAN Ultimate Collection (2018) | Hypothesis, baseline, Build-Measure-Learn, value-stream, muda, standard work, Five Whys, DMAIC-style control | Compilation is uneven and historical; exact standards still require authoritative verification |

## Research engine changes

- `source-evaluation`: added claim-specific freshness classes, incomplete/corrupted source quarantine, uncertainty-register fields, and a Kaizen handoff.
- `source-verification`: added currentness/completeness checks, product-release audit requirements, capped audit/remediation contract, and a post-wave learning loop.
- `research-orchestration`: added a reproducible wave-level experiment and standardisation loop with guardrail measures.
- `evidence-claim-graph`: added explicit hypothesis, experiment, measurement, and learning records.
- Cross-cohort synthesis reference: added uncertainty travel, warrant requirements, and next-wave improvement evidence.
- Product audit reference: added decision fit, provenance, claim graph, verification, uncertainty, reproducibility, usability, safety, and release dimensions.

## Linux engine changes

- Added a safe reversible operations standard covering authority, before-state capture, dry-run/no-op behavior, idempotence, atomic writes, family mapping, rollback, and recovery evidence.
- Added a value-stream/5S/QC Story reference covering operational waste, repository/runbook hygiene, root-cause analysis, small countermeasures, and standardisation.
- Added a two-family validation/recovery reference requiring explicit Debian-family and RHEL-family evidence, negative-path testing, idempotence, filesystem-aware recovery, and unassessed labeling.
- Added an incident-learning standard covering timeline, evidence-supported mechanism, containment, recovery, blameless accountability, standardisation, and re-measurement.
- Added a Linux product-audit checklist with the 65 cap and 95 target.
- Linked these standards from the Linux hub, Bash scripting, service management, repo sync, troubleshooting, disaster recovery, observability, log management, benchmark scanning, and the Kaizen meta-skill.
- Added explicit routing from Linux to the Digital Research engine for current or uncertain claims.

## Verification posture

Historical and partial sources remain labeled. No raw book text, OCR, or reconstructed content was copied into either repository. Commands and current platform/security/legal claims remain subject to live source verification and real-host validation.

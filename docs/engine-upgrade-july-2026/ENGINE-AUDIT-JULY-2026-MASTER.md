## Cross-Cutting Themes

- Most engines have strong breadth but insufficient finished, audited exemplar deliverables.
- Cross-engine routing is now a common pattern, but few engines have automated handoff contract tests.
- Anti-slop language exists in several engines; rendered-output proof and before/after examples lag behind.
- Currency is the most common compliance risk: volatile standards, platforms, tax rates, AI guidance, and security baselines need dated source registers.
- Empty directories, local project workspaces, and missing frontmatter create avoidable discovery noise.

## Portfolio-Level Recommendations

1. Create a shared `source-registers/` pattern with fields for source, effective date, checked date, reviewer, next review, and impacted skills.
2. Create a shared exemplar library: one complete, sanitized workflow per engine, each with inputs, outputs, QA verdicts, and evidence pack.
3. Standardize cross-engine handoff contracts for design, finance, research, documents, spreadsheets, and security.
4. Add portfolio-wide routing validation that globs every engine and fails on missing frontmatter, duplicate active names, and unresolved cross-engine references.
5. Build a shared document/workbook/render QA harness so Markdown, DOCX, XLSX, PDF, deck, and UI outputs can be inspected consistently.

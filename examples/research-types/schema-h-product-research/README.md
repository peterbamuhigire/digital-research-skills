# Schema H Exemplar - Product Research

Last verified: 2026-07-08
Benchmark: Product strategy research pack with evidence-backed jobs-to-be-done.

## Context

The product question is which digital service component should be piloted first: information lookup, document preparation, queue/status updates, payment support, or helpdesk escalation.

## Wave Log

| Wave | Purpose | Output |
|---|---|---|
| 1 | User job discovery | Jobs, pains, current alternatives |
| 2 | Concept risk | Assumption map and prototype evidence needs |
| 3 | Verification | Evidence check for user quotes and market claims |
| 4 | Synthesis | Prioritised product bet and experiment design |

## Evidence Table

| Claim ID | Claim | Evidence type | Verification status |
|---|---|---|---|
| H-C1 | Product priority follows task criticality. | Method rule | Valid |
| H-C2 | Willingness to use must be observed or tested. | Assumption | Needs pilot evidence |
| H-C3 | Feature requests are not proof of value. | Anti-pattern | Enforced |

## Final Report Specimen

The first product bet should be framed as a testable service hypothesis: for which user, during which border task, under what constraint, with what measurable behaviour change.

## Gate Verdict

Status: pass as exemplar. Live report fails if it jumps from anecdotes to roadmap commitments without evidence.

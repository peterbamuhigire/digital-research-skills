# Schema A Exemplar - Pain-Point Research

Last verified: 2026-07-08
Benchmark: McKinsey-style customer insight pack with evidence-register discipline.

## Context

Chwezi Core Systems examines trader, transporter, official, and intermediary pain points in a proposed cross-border trade digitisation pilot. All named facts are placeholders until verified in a project source register.

## Wave Log

| Wave | Purpose | Output |
|---|---|---|
| 1 | Broad cohort scan | Four cohort evidence tables and initial pain taxonomy |
| 2 | Gap fill | Device access, trust, fee, and workflow uncertainty log |
| 3 | Verification | Quote/stat/source manifest and archive gaps |
| 4 | Synthesis | Prioritised pain points by severity, frequency evidence, and solvability |

## Evidence Table

| Claim ID | Claim | Evidence type | Verification status |
|---|---|---|---|
| A-C1 | Paperwork complexity is a reported burden. | Synthesis from interviews and documents | Requires live source IDs |
| A-C2 | Device access is a load-bearing uncertainty. | Gap | Must be measured before recommendation |
| A-C3 | Trust in enforcement use affects adoption. | Inference | Needs direct cohort evidence |

## Final Report Specimen

The strongest provisional pain point is not "lack of an app"; it is uncertainty in the trader journey. The pilot should therefore test whether a digital service reduces specific administrative steps, not whether traders like digital tools in general.

## Gate Verdict

Status: pass as exemplar, fail as live evidence. No live statistic ships until Wave 3 verification confirms it.

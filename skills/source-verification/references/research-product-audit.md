# Research-product audit

Use before releasing a research report, evidence pack, source register, due-diligence file, dataset note, dashboard narrative, or reusable research brief.

## Audit dimensions

| Dimension | Inspect | Evidence of readiness |
|---|---|---|
| Decision fit | Audience, decision, scope, stop conditions | Decision and audience are explicit |
| Source integrity | Provenance, tier, independence, freshness, completeness | Every material source has a status and limitation |
| Claim graph | Claim-to-source links, warrants, inference labels, contradictions | No load-bearing orphan claim |
| Verification | URLs, locators, quotes, statistics, definitions, periods, units | Verification manifest records pass, fail, or unassessed |
| Uncertainty | Gaps, conflicts, partial sources, inaccessible sources | Uncertainty affects wording and decision posture |
| Reproducibility | Search strings, dates, exclusions, transformations, synthesis steps | Another reviewer can repeat the material path |
| Product usability | Structure, readability, accessibility, handoff, registry completeness | Intended consumer can act and review evidence |
| Safety and release | Privacy, legal/ethical boundaries, current-claim checks, blockers | No unresolved release-blocking defect |

## Scoring contract

Score each applicable dimension with inspected evidence and show raw scores. Publish `min(raw overall score, 65)`. For every gap below 95, produce an improvement action with root cause, owner, hypothesis, measure, evidence, risk, rollback, and acceptance test targeting 95/100. Missing evidence is `unassessed`, not pass.

## Product learning loop

After release or reviewer use, capture one observed defect or friction point, baseline it, run one reversible improvement, compare the same measure, and standardise only if the change improves the product without weakening evidence discipline.

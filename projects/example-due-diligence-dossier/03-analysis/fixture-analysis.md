# Fixture Analysis - Example Due-Diligence Dossier

This fixture analysis exercises the due-diligence workspace contract while avoiding live allegations or entity claims. The load-bearing conclusion is that a due-diligence example must prove identity, source traceability, risk reasoning, and output readiness before any dossier can be treated as release-ready.

## Argument Map

The governing thesis is that the workspace is valid as a structural example only. The reasoning sequence is local fixture source -> supported fixture claim -> verified synthesis -> tradecraft note -> evidence-dossier output shape. That sequence is enough for validator coverage but not enough for live due-diligence findings.

## Evidence Trail

The source trail starts at `SRC-0001`, which is marked as a local fixture. It supports `CLM-0001`, which supports `SYN-0001`. The tradecraft record identifies fixture overclaiming as a bias risk, and the productization manifest limits reuse to non-confidential validation.

## Assumptions and Warrants

The assumption is that example workspaces should pass the same registry gates as live projects. The warrant is quality control: if examples fail validation, users learn the wrong contract. The fixture therefore uses valid source tiers, claim statuses, synthesis statuses, and output-shape metadata.

## Countercase and Limitation

The countercase is that a due-diligence example could appear to endorse findings about a real person or organisation. This fixture avoids that risk by using no live entity, no adverse-media claim, and no sanctions assertion.

## Implication

The next action for a live due-diligence dossier is to replace fixture registries with registry extracts, adverse-media sources, sanctions checks, and reviewer sign-off before publication.
